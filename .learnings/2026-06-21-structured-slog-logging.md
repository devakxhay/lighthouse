# Structured Logging Integration with Go slog

This document describes the architectural changes implemented in Lighthouse to integrate structured logging using Go's `log/slog` standard library package.

## Context

Lighthouse needed structured logging for easier operational debugging and grep-friendly log collection. The specification requires:
- Human-readable output in dev mode with color-coded level prefixes.
- JSON output in production with configurable levels (default INFO, debug enabled via environment variable).
- Dependency injection of loggers rather than relying on global logger variables within subpackages.
- Custom Chi HTTP logger middleware.

## Implementation Details

1. **Logger Wrapper (`internal/logger/logger.go`)**:
   - Implements `New(devMode bool)` and `Get()`.
   - In dev mode, utilizes a custom `DevHandler` that implements `slog.Handler` to format logs as `2006/01/02 15:04:05 LEVEL [COMPONENT] message key=value` with standard ANSI terminal colors for log levels.
   - In production mode, utilizes standard `slog.JSONHandler` writing to stdout.

2. **Constructor Injection**:
   - Rather than referencing a package-level logger, components like `DB`, `Detector`, `Manager` (nginx), `Manager` (systemd), `Generator` (ssl), and `Handler` (api) accept `*slog.Logger` in their constructors or factory methods.
   - Each package prepends a `"component"` key-value attribute (e.g. `slog.String("component", "db")`) so that all logs generated by that component are tagged automatically.

3. **HTTP Middleware**:
   - Implements a custom Chi middleware (`HTTPLogger`) wrapping responses to log request method, path, response status, execution duration, and caller IP.
   - Sets log level to `INFO` for 2xx/3xx, `WARN` for 4xx, and `ERROR` for 5xx.
